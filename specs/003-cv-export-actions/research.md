# Research & Technical Decisions: CV Copy Page, Markdown/PDF Exports & Header Relocation

**Feature**: `003-cv-export-actions`
**Spec**: [spec.md](./spec.md)

## Decisions & Technical Rationale

### 1. Pre-computed Static Markdown Artifacts

- **Decision**: Generate `/cv.md` and `/pt/cv.md` at build time via a dedicated script (`scripts/generate-cv-markdown.mjs`) directly from `src/content/cv.generated.json`, outputting to `public/` and `dist/`.
- **Rationale**:
  - Complies with Constitution Principle I ("Content Is Data, Not Markup") and Principle IV ("Renderer-Agnostic Core").
  - Produces real, crawlable static files accessible via HTTP GET, `curl`, and LLM agents with 0ms compute latency and 100% edge cacheability on Cloudflare.
  - Enables the client-side `[ Copy Page ]` button to fetch or embed the exact static markdown text without needing a runtime Markdown serialization library in the React bundle.
- **Alternatives Considered**:
  - *Client-side JSON-to-Markdown serialization*: Rejected because adding a Markdown serializer to the client bundle would exceed the 120 KB bundle gate.
  - *Dynamic Cloudflare Worker SSR endpoint*: Rejected because the site's deployment contract is an assets-only Worker (no script runtime) per Constitution Principle IV.

### 2. Clean Bilingual URL Structure

- **Decision**: Use canonical unprefixed routes `/cv.md` and `/cv.pdf` for English, and `/pt/cv.md` and `/pt/cv.pdf` for Brazilian Portuguese.
- **Rationale**:
  - In standard POSIX and HTTP URL conventions, `.md` and `.pdf` represent file extensions. Placing path segments after a file extension (e.g. `/cv.md/eng`) causes `curl`, LLM tools, wget, and browsers to misinterpret the resource as a directory hierarchy rather than a plain file.
  - Perfectly matches the site's established bilingual structure:
    - Root / Canonical: `/cv/`, `/cv.md`, `/cv.pdf`
    - Portuguese: `/pt/cv/`, `/pt/cv.md`, `/pt/cv.pdf`
    - Matches the pattern established by `/mcp/`, `/mcp.md`, and `/pt/mcp.md`.
- **Alternatives Considered**:
  - `/cv.md/eng` and `/cv.md/ptbr`: Rejected due to POSIX/HTTP semantic violation and tool incompatibility.
  - Query parameters (`/cv.md?lang=pt`): Rejected because static assets on Cloudflare Workers serve discrete files by path without dynamic query routing.

### 3. Client Bundle Protection (< 120.00 KB Gzipped Gate)

- **Decision**: Implement the `[ Copy Page ] [ ▾ ]` action and dropdown menu using vanilla React state, semantic HTML, and lightweight inline SVG iconography, without importing external UI/icon libraries.
- **Rationale**:
  - Current client bundle size is 119.79 KB gzipped against the strict 120.00 KB gate (`scripts/check-bundle.mjs`), leaving ~210 bytes of margin.
  - Importing `@radix-ui/react-dropdown-menu` or icon libraries like `@lobehub/icons` or `lucide-react` would add 2-6 KB gzipped and immediately break the build gate.
  - An accessible, micro-component with standard keyboard (`Esc`, `Enter`, click outside) and ARIA attributes (`aria-haspopup="menu"`, `aria-expanded`) achieves full WCAG AA compliance with minimal byte footprint.
- **Alternatives Considered**:
  - *Full Radix DropdownMenu*: Rejected due to bundle size (> 3 KB gzipped).
  - *Icon packages*: Rejected due to bundle size and React 19 peer dependency warnings.

### 4. PDF Distribution & Cloudflare Edge Routing

- **Decision**: Route `/cv.pdf` and `/pt/cv.pdf` to the pre-compiled versioned PDFs in `public/cv/` via `public/_redirects`. Cloudflare R2 serves as the remote durable storage bucket updated by CI in `curriculum-vitae`.
- **Rationale**:
  - `howzysolutions.com` is hosted as static assets on Cloudflare edge. Routing requests through `_redirects` (or static symlinks/copies) provides sub-5ms TTFB globally with 0ms Worker execution time and no bandwidth fees.
  - The R2 bucket `howzysolutions` (`cv/eng/` and `cv/ptbr/`) holds the durable backup artifacts generated by `curriculum-vitae` CI.
- **Alternatives Considered**:
  - *Direct Worker streaming from R2*: Rejected because `howzysolutions` has no Worker script (assets-only deployment).
